## ADR-0012 — Permissions are a Domain Policy (not Infra configuration)

**Status:** Superseded by ADR-0021

### Context & Rationale

The module defines a set of permissions used by business rules and auditing (e.g., ActionLog required permission).

Previously, the permission enum lived under Infra config. That implied a dependency from domain entities/value objects/use cases to Infra, which breaks Clean Architecture dependency direction.

The permission set itself is part of the module’s ubiquitous language and represents a **policy** of the module.

### Decision

The permission model (e.g., `GoalsModulePermission`) MUST live in the **Domain** as a policy.

Canonical location:

* `lib/src/core/domain/policies/goals_module_permission.dart`

Infra remains responsible for:

* mapping host-app roles/users to these permissions
* providing access-control implementations

### Consequences

* Domain no longer depends on Infra.
* Permission semantics become stable and portable.
* Infra config focuses on integration/mapping rather than defining domain concepts.
