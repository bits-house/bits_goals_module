## ADR-0007 — Persistence implementations live in Infra

**Status:** Superseded by ADR-0013, ADR-0014, ADR-0018

### Context & Rationale

As stated in ADR-0001, this module must integrate with **any host app**.

Different apps may use:

* Firestore
* REST APIs
* SQL databases
* other persistence mechanisms

Persistence therefore **depends on the main app**.

### Decision

* **Database and API implementations** live in **Infra**
* **Their contracts (interfaces)** remain in the **Data layer**

> Note: This ADR is kept for historical context. The current, more precise rules are defined in ADR-0013, ADR-0014, and ADR-0018.
>
> **DO NOT USE THIS ADR AS A REFERENCE FOR NEW CODE.**
>
> - Domain repository contracts live in **Domain** (ADR-0014, ADR-0018)
> - Data source contracts live in **Data**, with IO/SDK-backed implementations in **Infra** (ADR-0013, ADR-0014)
> - Transaction-aware integration interfaces belong to **Application Ports** and may be implemented as adapters in **Data** (ADR-0018)

### Consequences

* Host app controls persistence integration
* No persistence lock-in inside the module
