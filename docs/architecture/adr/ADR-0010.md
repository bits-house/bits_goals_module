## ADR-0010 — Use Cases live in the Application layer (not Domain)

**Status:** Accepted

**Supersedes:** ADR-0005

### Context & Rationale

The project follows Clean Architecture (ADR-0002) and is structured into Core, Features, and Infra (ADR-0003).

Over time, some use cases and their supporting types (params/failures) were placed under `domain/` folders. This created a semantic mismatch:

* **Domain** should contain business rules and domain language (entities, value objects, domain services).
* **Use cases** are **application orchestration**: they coordinate permissions, ports, repositories, and domain services.

Keeping use cases in `domain/` invites domain → technical dependencies (even if “only interfaces”), and blurs the boundary between business rules and orchestration.

### Decision

Use cases MUST live in the **Application layer**.

Placement rules:

* Feature-specific use cases go to `lib/src/features/<feature>/application/use_cases/...`
* Shared/common use case abstractions go to `lib/src/core/application/use_cases/...`
* Domain remains focused on entities/VOs/domain services and policies.

### Consequences

* Clearer semantic separation: **Domain = business rules**, **Application = orchestration**.
* Easier to reason about dependencies: Application depends on Domain, not the inverse.
