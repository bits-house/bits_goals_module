# ADR-0012 — Permissions are Domain Enums (Capability Descriptors)

**Status:** Accepted  
**Supersedes:** Previous ADR-0012 (“Permissions are a Domain Policy”)

## Context

The module defines a finite set of permissions (e.g., `GoalsModulePermission`) used to:

- Guard use cases  
- Control UI access  
- Support auditing

Previously, permissions were classified as a **Domain Policy** and placed under `domain/policies/`.

A similar architectural clarification occurred with `Currency`, which was classified as a **Domain Enum** representing a bounded domain concept.

This re-evaluation of `Currency` triggered a broader review of enum-based domain concepts, leading to the same conclusion for permissions.

Both:

- Do not implement behavior  
- Do not define strategies
- Do not contain decision logic
- Represent closed sets of domain concepts

They define *what exists*, not *how it behaves*.

## Decision

`GoalsModulePermission` MUST be defined as a **Domain Enum** representing capability descriptors.

Canonical location:
- `lib/src/core/domain/enums/goals_module_permission.dart`

## Consequences

- Clear separation between capability definition (Enum) and authorization logic.
- Improved semantic accuracy in folder structure.
- Future evolution to richer authorization models remains possible.
