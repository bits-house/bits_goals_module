## ADR-0003 — Divide the module into Core, Features, and Infra

**Status:** Accepted

### Context & Rationale

As the module grows, mixing shared logic, feature-specific logic, and infrastructure leads to:

* tight coupling
* unclear responsibilities
* difficulty scaling the codebase

### Decision

Divide the module into three main areas:

* **Core**
* **Features**
* **Infra**

> Note: Infra is outside of the core folder because it contains the data sources implementations and other infrastructure-related code, which may be modified or replaced by the host app without affecting the core logic.

Detailed responsibilities are defined in the following ADRs.

### Consequences

* Clear architectural boundaries
* Easier long-term evolution
