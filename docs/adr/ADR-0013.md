## ADR-0013 — IO/network-backed data source implementations live in Infra (not Data)

**Status:** Accepted

### Context & Rationale

ADR-0008 allowed some data source implementations to live in the Data layer when they do not depend on the host app.

In practice, some “not host-app dependent” implementations still depend on **external SDKs** and/or perform **real IO** (e.g., network calls, `dart:io`). These are infrastructure concerns and violate the intent of keeping inner layers framework/technology-agnostic.

A concrete example is the remote time implementation (`RemoteTimeDataSourceImpl`) which relies on NTP/HTTP and therefore performs network IO.

This decision aligns with ADR-0006 (Infra contains technology- and app-dependent code).

### Decision

- Data sources **contracts** remain in the Data layer.
- Data source **implementations** that perform **IO** or depend on **external SDKs** (e.g., HTTP clients, NTP packages, `dart:io`) MUST live in **Infra**.
- The Data layer may still contain **pure** implementations that are deterministic, in-memory, and do not require platform/network IO.

Canonical placement:

- Contract: `lib/src/core/data/data_sources/...`
- IO/SDK-backed implementation: `lib/src/infra/data_sources/...`

### Consequences

- Cleaner dependency direction: Data no longer depends on IO/network details.
- Some implementations move from Data to Infra even if they’re not host-app dependent.
